# 桌面端轻量版主架构实现文档

这份文档是新桌面端应用的主文档，目标不是介绍概念，而是给开发提供一份可以直接照着落地的总体实现说明。

文档约束如下：

- 新软件是桌面端，不使用微服务、MQ、积分、权限后台、多模型调度
- 只保留从剧本到完整视频的主生产链路
- 只接火山引擎系列能力：豆包文本、生图、视频、语音
- 所有生成动作遵循统一任务模板，通过本地任务队列调度

## 1. 目标产品定义

新应用是一个本地优先的桌面创作工具。用户从一个项目开始，导入剧本后，系统完成以下工作：

1. 创建项目和工作区
2. 导入剧本
3. 自动拆分片段
4. 为每个片段创建剧本任务
5. 从剧本抽取角色、场景、物品
6. 生成人物、场景、物品资产图
7. 基于剧本和资产生成分镜
8. 编辑分镜
9. 生成分镜融合图
10. 生成语音
11. 生成视频片段
12. 合成导出完整成片

## 2. 技术栈

- 桌面壳：`Tauri 2`
- 前端：`React 18 + TypeScript + Vite`
- 本地数据库：`SQLite`（通过 better-sqlite3 或 rusqlite）
- 查询缓存：`TanStack Query v5`
- 轻量状态：`Zustand`
- 任务执行：`Node worker`（sidecar 进程，通过 stdio 与 Tauri 通信）

选择 Node sidecar 而非 Rust 原生执行的原因：火山引擎 SDK 以 Node/Python 优先；团队技术栈以 JS/TS 为主；FFmpeg/SQLite/HTTP 轮询在 Node 侧有成熟库支持。stdio 通信开销对于秒级 AI 生成任务可忽略（详见模块 08 第 3.4 节）。

- 媒体处理：`FFmpeg / FFprobe`
- 模型能力：火山引擎（豆包文本、生图、视频、语音）

## 3. 分层架构

### 3.1 桌面壳层（Tauri）

负责窗口、菜单、文件选择、系统路径、更新、日志目录。提供 IPC 命令供前端调用，管理 Node worker 进程的生命周期。

### 3.2 前端交互层（React）

负责项目列表、工作台、分镜编辑器、任务中心、导出页。通过 Tauri IPC 命令与后端通信，通过 TanStack Query 管理数据缓存，通过事件流订阅任务进度。

### 3.3 领域编排层

负责项目、片段、剧本、资产、分镜、任务状态机。这一层在 Tauri 的 Rust/TS 服务层中实现，处理业务校验、状态推进、参数继承和失效标记。

### 3.4 任务运行层

负责所有本地异步任务。Node worker 从 SQLite 取 pending 任务，获取逻辑锁，执行具体逻辑（调用火山引擎 API、下载文件、回写业务状态），通过事件流推送进度。详见模块 08。

### 3.5 模型适配层

负责火山引擎调用，四类客户端：

- `VolcanoTextClient`：豆包文本模型（剧本拆分、剧本理解、分镜生成）
- `VolcanoImageClient`：火山生图模型（资产图、分镜融合图）
- `VolcanoVideoClient`：火山视频模型（视频片段生成）
- `VolcanoVoiceClient`：火山语音模型（TTS 语音生成）

### 3.6 媒体处理层

负责本地下载、转码、时长探测、拼接、导出。使用 FFmpeg/FFprobe 完成所有媒体操作，不依赖远程服务。

## 4. 核心设计原则

这些原则贯穿所有模块，是整个系统的设计基础。

### 4.1 统一生成任务模板

所有耗时动作（剧本拆分、剧本理解、资产生图、分镜生成、融合图生成、语音生成、视频生成、导出）都遵循同一套任务模板：

1. 校验输入（必填字段、前置条件、逻辑锁）
2. 持久化任务和业务状态（同一 SQLite 事务）
3. 提交远端请求（事务提交后异步执行）
4. 轮询或等待回调
5. 回写结果（下载文件、更新业务状态、释放锁）
6. 失败补偿（标记失败、保留错误信息、释放锁）

事务边界只覆盖"写入 Task 记录 + 更新业务状态"这一步。远端请求、文件下载在事务外执行。详见模块 08 第 2 节。

### 4.2 先记录后异步

UI 提交后只做两件事：校验输入、在同一事务中写入 Task 和业务状态。提交后立即返回，不等待远端结果。前端通过事件流订阅任务进度。

这意味着：
- 剧本导入后先保存 `ScriptSource`，再入队拆分任务
- 剧本理解先保存 `ClipScript`，再入队生成任务
- 资产生图先保存 `Asset`，再入队图像任务
- 分镜生成先保存 `Storyboard`，再入队生成任务

### 4.3 业务记录与任务记录分离

所有生成动作产生两类记录：

- 业务表：`Project`、`ScriptSource`、`Clip`、`ClipScript`、`Asset`、`Storyboard`
- 任务表：`Task`

业务表记录当前状态和最终结果，任务表记录执行过程和输入输出。结果路径可以收敛进 `Task.outputJson`，不再拆成很多结果表。

### 4.4 状态推进与停止步骤

每个片段（Clip）独立维护 `currentStep` 字段，独立推进步骤。项目的 `currentStep` 是聚合值，取所有片段中最慢的步骤。用户可对不同片段并行操作，无需等待所有片段同步推进。`autoContinue` 和 `stopStep` 仍为项目级配置，作用于每个片段的自动推进逻辑。

每一步完成后，如果 `autoContinue = true` 且 `stopStep` 未命中当前步骤，自动推进到下一步并创建对应的 Task。否则停住等待用户手动触发。

步骤序列：`project → split → script → asset → storyboard → voice → video → export`

### 4.5 资产与分镜同步

资产变更后，必须同步到引用该资产的所有分镜：

- 如果分镜尚未生成融合图，只更新引用关系
- 如果分镜已生成融合图，标记 `imageState = invalidated`，提示用户重新生成

参数合并规则：项目默认参数 → 分镜级参数覆盖（浅合并）。

### 4.6 失效而非删除

当上游变更时，下游不直接删除已有结果，而是标记为 `invalidated`：

- 台词变更 → 语音失效 + 视频失效
- 画面描述或图像提示词变更 → 融合图失效 + 视频失效
- 视频提示词变更 → 视频失效
- 引用资产变更 → 融合图失效 + 视频失效
- 顺序变更 → 仅导出时间线失效

UI 显示"需重新生成"标记，用户手动触发重算。

### 4.7 防重复执行

同一 `clipId + taskType` 不允许并发两条运行中任务。同一 `storyboardId + taskType` 不允许并发重入。通过 SQLite 逻辑锁（`task_locks` 表）实现，锁有 30 分钟超时自动清理。

### 4.8 重启恢复

应用启动时扫描所有 `running`、`waiting_remote`、`downloading` 状态的 Task：

- 本地可重跑任务回退为 `pending`
- 远端轮询任务恢复轮询（如果有 `remoteTaskId`）
- 清理过期逻辑锁

### 4.9 页面工作流

前端使用三栏工作台：

- 左栏：项目树（项目列表 → 片段列表 → 分镜状态）
- 中栏：主编辑区（按 `currentStep` 切换视图）
- 右栏：任务与参数（当前参数、任务状态、失败信息、快捷重试）

不使用传统路由，而是基于 `currentStep` 的视图切换。

    desktop/

## 6. 核心领域对象

### 6.1 Project

项目是工作区容器，持有：项目名称、工作区路径、输入模式、风格模式、当前步骤、停止步骤、自动继续标记、默认图像参数、默认视频参数、默认语音参数。

### 6.2 ScriptSource

表示一份原始剧本输入。保存：原始内容、规范化内容、来源文件名、输入类型、拆分任务状态。

### 6.3 Clip

片段是剧本拆分后的可制作单元。保存：顺序号、标题、摘要、片段正文、字数/预估时长、片段状态。

### 6.4 ClipScript

片段剧本生成任务对象。保存：原剧本文本、优化剧本文本、模型输出的角色/场景/物品、当前步骤、停止步骤、错误信息。

### 6.5 Asset

资产统一抽象角色、场景、物品。保存：类型、名称、描述、参考图、生图提示词、最终图路径、缩略图路径、所属项目/片段。

### 6.6 Storyboard

分镜是整个系统的主工作单元。保存：所属片段、镜号、画面描述、台词、角色/场景/物品引用、生图提示词、生视频提示词、语音参数、图像参数、视频参数、图状态/语音状态/视频状态、融合图路径、语音路径和时长、视频路径和时长。

### 6.7 Task

所有耗时动作都落成任务。保存：类型、状态、逻辑锁键、输入参数、输出结果、远端任务 ID、错误信息、重试次数、开始时间、完成时间。

## 7. 全链路实现方式

### 7.1 项目创建

项目创建不是只保存项目表，而是把项目、工作区、数据库、默认参数和初始任务同时建立起来。两种输入模式：

- 空项目：只创建项目和工作区
- 剧本项目：额外保存 `ScriptSource`，创建拆分任务

详见模块 01。

### 7.2 剧本导入与拆分

剧本导入后先做文本规范化（统一换行、全角转半角、引号配对、剔除设定部分、乱码检测），然后走两段式拆分：

1. 本地规则拆分：正则匹配集数标志（第X集、EP.X、场景X 等），快速切分
2. 模型智能拆分：规则不匹配时，调用豆包文本模型做语义切分，长文本分块处理

拆分输出 `Clip[]`，每个片段有标题、摘要、正文和预估时长。详见模块 02。

### 7.3 剧本理解与资源抽取

剧本理解是一个异步任务，对每个片段调用豆包文本模型，输出：

- 片段摘要
- 角色候选列表
- 场景候选列表
- 物品候选列表
- 建议的生成模式

用户确认资源后生成 `Asset` 记录，进入资产生图队列。资源校验：角色和场景不能同时为空。详见模块 03。

### 7.4 资产图生成

资产生图调用火山生图模型，每个资产一个任务。支持批量生图（当前片段全部资产、当前项目全部角色、全部未生成资产）。生成后下载图片到工作区，生成缩略图，回写路径。

资产变更后同步到引用该资产的分镜：未生成融合图的只更新引用，已生成融合图的标记失效。详见模块 04。

### 7.5 分镜生成与编辑

分镜生成前做 10 项前置校验（项目ID、片段ID、角色场景不能同时为空、资产必须有图、名称不能重复、剧本已完成等）。校验通过后调用豆包文本模型生成结构化分镜，输出镜号、画面描述、台词、角色/场景/物品引用、生图提示词、生视频提示词。

分镜编辑支持改镜号、台词、画面描述、引用资产、提示词和参数。任何改动根据失效规则矩阵触发下游失效。详见模块 05。

### 7.6 分镜融合图

分镜融合图按分镜引用关系生成最终镜头图。每条分镜一个 `generate_storyboard_image` 任务，支持批量入队。支持上传本地替代图和回滚到上一次结果。

### 7.7 语音生成

两种语音来源：

- 本地语音：复制到工作区，探测时长，直接标记完成
- 火山 TTS：创建任务，请求火山语音模型，轮询，下载，探测时长，回写

完成后必须把时长回写到分镜，用于后续视频长度和导出拼接。台词变更联动失效语音和视频。详见模块 06。

### 7.8 视频生成

两种视频生成模式：

- `image_to_video`：有融合图，用融合图作为首帧生成视频
- `reference_image_to_video`：用角色/场景/物品参考图直接生成视频

前置校验：融合图/参考图必须存在、视频提示词必须存在、参数必须完整、分镜未被标记失效。生成后下载视频，回写路径和时长。详见模块 07。

### 7.9 导出

导出完全本地化，不依赖远程服务：

1. 读取已完成的视频片段
2. 读取分镜顺序和剪切点
3. 读取音频和字幕
4. 本地 FFmpeg 合成
5. 写出最终 MP4

支持配置分辨率、帧率、字幕、背景音乐。导出前检查所有分镜视频文件是否存在。详见模块 07。

## 10. 验收标准

这套文档对应的新应用，最少要满足这些条件才算可开发、可上线内部使用：

1. 用户能创建本地项目
2. 能导入剧本并拆成片段
3. 能为片段生成结构化剧本结果
4. 能抽取角色、场景、物品并生成资产图
5. 能生成、编辑分镜
6. 能生成分镜融合图
7. 能生成语音
8. 能生成视频片段
9. 能导出完整成片
10. 任一步失败后都能重试并恢复
